## 1. 项目背景与目标（为什么做这个）

UCI Student Performance 数据集是机器学习教学中的经典 tabular 数据集，包含学生背景、家庭、学习习惯等特征，目标是预测数学（mat）或葡萄牙语（por）课程的最终成绩 G3（0-20 分）。

** 我们的核心问题定义** ：
- ** 回归任务** ：精确预测 G3 分数
- ** 分类任务** ：预测“是否通过”（G3 ≥ 10 定义为 pass）

** 更深层的教育目标** ：发现“学业失败是累积过程”，找到最佳早期干预窗口，并交付一个老师真正能用的工具（而非只报准确率）。

最初 README 规划了清晰的 A/B/C 分工和阶段依赖，但实际执行中遇到了大量对齐问题，最终通过多次迭代修复才达到当前状态。

## 2. 数据是怎么拿到的、最初长什么样

### 2.1 数据来源
- 来源：UCI Machine Learning Repository - Student Performance Data Set
- 主要文件：
  - `student-mat.csv`（395 条，数学课程，主用）
  - `student-por.csv`（649 条，葡萄牙语课程，用于泛化实验）
  - `student.txt`（完整字段说明）
- 获取方式：手动下载后放置到 `data/raw/`（A 负责收集原始 CSV）。

### 2.2 初始数据状态（2026 年 5 月初）
- 原始 CSV 用 `;` 分隔。
- 33 个原始特征 + G3 目标。
- ** 关键字段** ：
  - G1、G2、G3：三次成绩（G3 是最终目标）
  - 人口/家庭：school, sex, age, address, famsize, Pstatus, Medu, Fedu, Mjob, Fjob...
  - 学习相关：traveltime, studytime, failures, schoolsup, famsup, paid, activities...
  - 社交/健康：famrel, freetime, goout, Dalc, Walc, health, absences, romantic...

** 最初问题** ：
- 没有 `data/raw/data_description.md`（后来补）。
- 没有人真正“拆解”数据，notebooks 直接开始清洗。
- 两个 CSV 存在，但最初只用 mat。

## 3. 数据拆解与关键洞见发现（A 主导）

### 3.1 探索路径（notebooks/01_data_exploration.ipynb）
- 初先加载 mat，检查缺失值（0）、重复（有）、类型。
- 描述性统计：G3 均值 ~10.4，及格率约 67%，absences 有极端值（最大 75）。
- 相关性分析（最重要一步）：
  ```python
  # 核心发现
  G2 与 G3 corr = 0.9048679892693007
  G1 与 G3 corr = 0.8014679320174141
  failures 与 G3 corr = -0.3604149404616498
  ```
- 可视化：G1/G2/G3 箱线图、散点矩阵、缺失热力图等。
- ** 洞见提炼** （后来成为项目灵魂）：
  > “G2 是压倒性最强预测因子，学业具有极强的累积性/路径依赖。”

这个洞见在第 1 个 notebook 就掘出来了，但后面花了大量时间才把它“工程化”和“量化”。

### 3.2 为什么这个洞见这么重要？
后续所有模型的 feature importance 都验证了它：
- 回归 RF：G2 贡献 ~79%
- 分类 RF：G2 贡献 ~35%（仍远超其他特征）

这直接驱动了后面的 **G2 Baseline 实验** 和 **What-If 干预模拟** 。

## 4. 预处理模块的演进（A 核心，坑最多）

### 4.1 最初状态（混乱期）
- notebooks/02_preprocessing.ipynb 自己写了一整套清洗 + split + OneHot + Scale 逻辑。
- `src/preprocess.py` 初期版本存在严重问题：
  - `encode_categorical` 只 fit、不 transform（返回原始 df）。
  - `run_pipeline` 在全量数据上 fit preprocessor（** 数据泄露** ）。
  - 硬编码 categorical/numeric 列表。
  - clean 和 notebook 逻辑不一致（row filter vs quantile clip）。
  - 保存时带 "Unnamed: 0"（index 污染）。
- notebooks 完全不调用 src 的 Preprocessor，形成“两套系统”。

** 最严重后果** ：B 训练时拿到的 X 带垃圾列，模型学到无意义特征。

### 4.2 重大修复阶段（review_1 后）
参考 `report/review_report_1.md` 的 P0/P1 问题列表，执行了系统性修复：

1. ** Unnamed:0 污染** ：所有 `to_csv(..., index=False)` + 重新生成 processed 数据。
2. ** 泄露修复** （核心）：
   ```python
   # 正确顺序（run_pipeline 最终版）
   df_clean = clean(df_raw)
   X, y = split_features_target(df_clean, "G3")
   X_train, X_test, ... = split_train_test(...)   # 先 split
   # 然后只在 train 上 fit ColumnTransformer
   preprocessor = ColumnTransformer(...)
   X_train_encoded = preprocessor.fit_transform(X_train)
   ```
3. ** 动态特征识别** ：不再硬编码，`select_dtypes` 在 train 上跑。
4. ** notebooks 对齐 src** ：nb02 改为调用 `Preprocessor.run_pipeline`，成为单一事实来源。
5. ** 新增 feature_engineer** （后期 C 推动）：
   - `grade_trend = G2 - G1`
   - `parent_edu = (Medu + Fedu) / 2`
   - `alc_total = Dalc + Walc`
   - `study_fail_interact = studytime * (failures + 1)`
   - 通过 `run_pipeline(..., feature_engineer=True)` 开启。

** 当前推荐用法** ：
```python
from src.preprocess import Preprocessor
p = Preprocessor()
res = p.run_pipeline("student-mat.csv", "G3", feature_engineer=True)
# res 包含 X_train (array), feature_names, preprocessor 等
```

### 4.3 预处理模块最终职责
- `load_raw` / `clean`
- `feature_engineer`（可选）
- `run_pipeline`（推荐主入口）：load → clean → (fe) → split → fit CT on train only → 返回完整 dict
- 兼容旧接口（encode/scale 仍保留但加警告）

## 5. 模型与训练模块（B）

### 5.1 初始设计
- `src/models.py`：ClassifierFactory + RegressorFactory（严格 5+5）
- `src/config.py`：超参空间（TREE_PARAMS, RF_PARAMS, SVM_PARAMS... ）
- `src/train.py`：Trainer 类
  - `train_model`
  - `train_with_grid_search`（GridSearchCV + n_jobs=-1）
  - `save_model` / `load_model`

### 5.2 演进与扩展
- 后期扩展到 6+6（加入 GradientBoostingClassifier/Regressor）
- Config 补全 `GB_PARAMS` + `CLASSIFIERS / REGRESSORS` 列表
- `_get_model_instance` 中安全设置 random_state（只对支持的模型设置）

** B 的 notebook 流程** （ 03/04 ） ：
1. 加载 A 产出的 `X_train.csv` + y（分类需立即 binarize ）
2. 实例化 Trainer
3. 训 5 个 base model + 1 个 tuned（RF / Ridge）
4. cross_validate 得到 CV 指标，保存到 outputs/tables
5. 保存所有 joblib 到 outputs/models

** 难点** ：
- 分类任务语义混乱（最初直接用 G3 做 18 类多分类）。
- 修复后全量重训 6 个 classification 模型。

## 8. 哪里最难？一步步是怎么优化的？

### 8.1 最大坑（P0 级别）
1. ** 数据泄露** （preprocess 在全量 fit ）
   - 症状：CV 分数虚高，test 表现差。
   - 解决：强制 run_pipeline 先 split 再 fit，notebook 也对齐。
2. ** 分类任务语义错误**
   - 最初把 G3 当多分类，cm 无意义。
   - 解决：统一 binarize (G3 >= 10)，全量重训模型。
3. ** 两套系统（notebook vs src）**
   - 解决：让 nb02 调用官方 Preprocessor，src 成为唯一真相。

### 8.2 中期优化
- 统一路径处理（chdir + ensure_dir）
- 所有保存加 `index=False`
- 测试从骨架补到 32 个真实集成测试
- artifacts 恢复 + .gitignore 白名单治理

### 8.3 后期创新优化（C 主导，加分项）
- ** G2 Baseline** ：不是简单“用 G2 预测”，而是用** 相同 split 的 raw G2** 做公平对比，真正量化“额外特征价值”。
- ** Cross-subject** ：用已 fit 的 preprocessor 转换 por，证明泛化。
- ** StudentRiskPredictor** ：从“研究代码”变成“可 demo 的产品代码”，支持 what-if 直接服务教育场景。
- ** feature_engineer** 反向补到 A 模块，让预处理支持教育洞见特征。

** 关键决策** ：后期没有继续堆模型（XGBoost 等），而是把精力放在“让 G2 这个洞见可量化、可验证、可落地”上，这比多跑几个模型更有故事性。
